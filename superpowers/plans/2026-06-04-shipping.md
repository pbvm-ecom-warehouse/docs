# Module Shipping — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Viết bộ tài liệu module Shipping (vận chuyển) cho hệ WMS-ECOM và cập nhật các file liên đới để mô tả nhất quán luồng giao hàng end-to-end.

**Architecture:** Đây là repo **tài liệu markdown tiếng Việt**, không có code/build/test. "Sản phẩm" là các file `.md`. Module mới = thư mục `shipping/` với bộ 3 file `use-cases.md` + `data-model.md` + `workflow.md`, cộng cập nhật 6 file liên đới. Nguồn chuẩn của thiết kế: [spec 2026-06-04](../specs/2026-06-04-shipping-design.md).

**Tech Stack:** Markdown. "Verify" = (1) anchor nội bộ khớp slug heading, (2) link `.md` trỏ file tồn tại, (3) định danh (collection/enum/event) khớp [data-ownership.md](../../overview/data-ownership.md). Không có test runner.

**Quy ước verify (dùng lặp lại ở mọi task):**
```bash
# Heading → slug (để đối chiếu khi link tới anchor)
grep -n "^#" <file>.md
# Link .md trỏ tới file — kiểm tra file tồn tại
grep -ohE '\]\(\.\.?/[^)#]+\.md' <file>.md | sed -E 's/\]\(//' | while read p; do test -e "$(dirname <file>.md)/$p" && echo "OK $p" || echo "MISSING $p"; done
```

**Slug tiếng Việt (GitHub):** lowercase, **giữ dấu**, bỏ `: ( ) / + & — .`, khoảng trắng → `-`, ký tự bị bỏ giữa 2 khoảng trắng tạo `--`.

**Thứ tự định danh đã chốt (nguồn: spec mục 3–5):**
- Collections (`wms_db`): `carriers`, `shipments`.
- Enum `shipmentStatus`: `PENDING / PICKED_UP / IN_TRANSIT / DELIVERED / FAILED / RETURNING / RETURNED`.
- Events mới (WMS→Ecom): `shipment.shipped`, `shipment.delivered`, `shipment.returned`.
- Event sửa payload (Ecom→WMS): `order.ready_to_fulfill` (+`shippingAddress`,`recipient{name,phone}`,`paymentMethod`,`codAmount`).
- Notification: `goods.issued → Notification` **thay bằng** `shipment.shipped → Notification`.
- Use-cases: `UC-S01..UC-S05`. Workflow: `WF-S01`, `WF-S02`.

### Task 2: `shipping/data-model.md` — schema `carriers` & `shipments`

**Files:**
- Create: `shipping/data-model.md`

- [ ] **Step 1: Viết file data-model**

Cấu trúc file (theo giọng văn & format các `data-model.md` hiện có, vd [order/data-model.md](../../order/data-model.md)):

- Header: tiêu đề `# Shipping (WMS) — Data Model` + marker `> Trạng thái: 🔄 Đang phân tích`.
- Câu mở: chủ sở hữu = WMS (`wms_db`); liên kết đơn Ecom **chỉ qua `orderId` + event**, không đọc chéo; trỏ [data-ownership](../overview/data-ownership.md).
- `## carriers` — bảng field: `_id, name, code (duy nhất), status (ACTIVE/INACTIVE), contactInfo, note, apiConfig? (optional — chỗ chừa tích hợp API, chưa dùng)`.
- `## shipments` — bảng field đầy đủ theo [spec §3.2](../superpowers/specs/2026-06-04-shipping-design.md): `_id, orderId (id tham chiếu — KHÔNG đọc chéo), goodsIssueId, fulfillWarehouseId, carrierId, trackingNumber (nhập tay), shipmentStatus (enum), recipient {name,phone,address} snapshot, paymentMethod (COD/ONLINE), codAmount, attempts, failReason, statusHistory[] {status,at,by,note}, shippedAt, deliveredAt`.
- `## Enum shipmentStatus` — liệt kê 7 trạng thái + mô tả từng cái: `PENDING` (vừa sinh sau goods.issued, chưa gán hãng), `PICKED_UP` (hãng đã lấy), `IN_TRANSIT` (đang giao), `DELIVERED`, `FAILED` (thất bại 1 lần, có thể retry), `RETURNING` (bỏ cuộc, đang hoàn về), `RETURNED` (đã về kho).
- `## Quan hệ với Order (Ecom)` — bảng mapping `shipmentStatus` (WMS) → `fulfillmentStatus` (Order) theo [spec §4](../superpowers/specs/2026-06-04-shipping-design.md): chỉ `IN_TRANSIT→SHIPPED`, `DELIVERED→DELIVERED`, `RETURNED→RETURNED`; ghi rõ COD flip PAID khi DELIVERED, return-to-sender → `orderStatus=CANCELLED`. Nhấn mạnh **1 đơn = 1 vận đơn** (xuất nguyên kiện).

Trỏ link [warehouse UC-09](../warehouse/use-cases.md#uc-09-hoàn-hàng-return--rma).
